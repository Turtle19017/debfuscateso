# B1E90 white-box transform

## Role

`0xB1D68` is the block-wrapper reached from the VM-protected `FD7C4` unpack path.
It validates that the ciphertext length is a multiple of 16, allocates a temporary
buffer, calls `0xB1E90` once per 16-byte block, validates PKCS#7 padding and copies
the unpadded plaintext to the caller-provided output buffer.

High-level shape:

```text
B1D68(cipher, cipher_size, output, output_size)
    |
    +-- reject nulls / non-16-byte-aligned input
    +-- malloc(cipher_size)
    +-- for each 16-byte block:
    |      B1E90(cipher + off, temp + off)
    +-- validate PKCS#7
    +-- memcpy(output, temp, unpadded_size)
    +-- *output_size = unpadded_size
    +-- free(temp)
    `-- return 0 on success, -1 on failure
```

## `B1E90`

Sample range:

```text
entry  = 0xB1E90
return = 0xB968C
```

The routine is about 30 KiB of AArch64 and consists primarily of table lookups,
nibble packing/unpacking and SIMD/scalar bit movement. Static disassembly contains
7,680 instructions using only 36 mnemonics.

The only direct calls in the function are:

```text
memcpy@plt            x5
__stack_chk_fail@plt  x1 (failure-only)
```

This makes concrete emulation practical without Android/QEMU.

## Offline emulator

`tools/emulate_b1e90.py` interprets the AArch64 emitted by `llvm-objdump`. It maps
the sample ELF load ranges, applies `R_AARCH64_RELATIVE` relocations from `readelf`,
provides a local stack-guard value and emulates the instruction subset used by
this function.

A subtle but important instruction is:

```asm
0xB575C: ldr x10, [x16], #0x20
```

The post-index update is required. Omitting it produces plausible-looking but
incorrect plaintext. After implementing the update, the final sample ciphertext
block:

```text
a2e0d71c54379f3fbeddb69d88d941f8
```

maps to:

```text
10101010101010101010101010101010
```

which is the expected full-block PKCS#7 padding.

## Recovered small stage

Descriptor/raw-file mapping for this sample:

```text
small ciphertext offset = 0x4515A0
small ciphertext size   = 0x1010
```

Running all 257 blocks through `B1E90` and removing the 16-byte padding produces:

```text
small plaintext size   = 0x1000
SHA-256                = 41a5a08c5dee17f1cc42fa3a746d2c1fd16dee66969e603409b5773672d815f7
```

The next raw stage is:

```text
large ciphertext offset = 0x4525B0
large ciphertext size   = 0x2A2649
```

The ChaCha20 ciphertext is exactly:

```text
small_plain || large_ciphertext
```

with total size:

```text
0x2A3649
SHA-256 = 5598e539b16ec77164787c34a76b964d0bd63a799f3e9d9c8a45a7cf7ca425f3
```

## End-to-end validation

Using the recovered ChaCha20 parameters documented in `ADDRESS_MAP.md`, the first
plaintext bytes are:

```text
70 00 53 00 78 9c ...
```

Interpreted as:

```text
uint32_le size = 0x530070
zlib header    = 78 9c
```

Inflation yields the exact inner memory image:

```text
size    = 0x530070
SHA-256 = 5a0ff6b4e1d3bf811dbd1f2b5db3e48ae14c12fb6da5f5662bf2e3c7bd66f168
```

This closes the previously missing offline stage between the outer SO and the
inner ImGui/Dobby payload.
